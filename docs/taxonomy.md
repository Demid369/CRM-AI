# Таксономия сущностей — 3D-визуализация (РФ)

Канон для URL и CMS. Синоним ≠ страница. Спрос — относительный (high/mid/low) по паттернам Wordstat «дизайн/визуализация {X}»; абсолютные частоты в пилоте пробиваем Keys.so / Wordstat, без пробивки комбо не публикуем.

Три статуса URL:

| Статус | Что это | Индекс |
| --- | --- | --- |
| **хаб** | каноническая сущность, свой ЧПУ | index, в sitemap |
| **редирект** | синоним с живым спросом | 301 на канон, не в индексе |
| **тег** | метаданные проекта / UI-чип | URL нет; если фильтр — `?tag=`, noindex |
| **фильтр** | состояние каталога | `/raboty?...` noindex, follow; ЧПУ не плодим |

Порог хаба пилота: серия своих кадров + коммерческий текст, не Wikipedia. Порог комбо: ≥4 **studio**-кадра **этой** пары + ручные title/H1/intro + `wordstat_at`. «≥15–20 работ на комбо» — не стартовый порог, студия так не наберёт.

---

## 0. Слои, не декартово произведение

Индексируем оси **по отдельности** и только белые пары. Не `стиль × комната × объект × город × м²`.

```
хабы:   /stili/{style}  /komnaty/{room}  /eksterier  /eksterier/{style}
комбо:  /stili/{style}/{room}     только
каталог:/raboty   фильтр без индексного query-URL
проект: /raboty/{slug}   index только с паспортом
```

Нет `/obekty/*` и нет `/stili/{style}/kvartira`. «Квартира в стиле X» = хаб стиля. Тройные path запрещены.

### 1.2 Кластеры синонимов (жёстко)

**Зал = гостиная?** Да, в жилье. `/zal` → `/komnaty/gostinaya`. В H1/тексте хаба гостиной один раз сказать «зал». Коммерческий зал ресторана/отеля — тег проекта, не эта страница.

**Ванная / санузел / туалет / душевая** — один смысл для частника, три языка:

- частник ищет «ванную»;
- дизайнер/сметчик — «санузел»;
- «туалет» — отдельный WC, мало кадров, тонко.

Канон: `vannaya` всегда хаб. `sanuzel` — второй хаб **только** после пробивки; иначе 301 на ванную. `tualet` всегда 301. `dushevaya` — тег. Четыре индексные страницы сразу = каннибализация.

**Балкон / лоджия** — один хаб. Не два. Свап канона по частоте, не два индекса.

**Коридор / прихожая** — один хаб `prihozhaya`.

**Прачечная / постирочная** — один тег `postirochnaya`.

**Студия / open space** — не комнаты.

**Кухня-гостиная** — хаб. Не генерировать как пересечение фильтров кухня+гостиная.

## 4. Квадратура, комнатность, бюджет — страницы не делать

Это оси **каталога и карточки проекта**, не посадочных.

| Ось | Примеры | Спрос у дизайна/ремонта | Спрос у визуализации | Решение |
| --- | --- | --- | --- | --- |
| Комнатность | 1к, 2к, 3к, 4к, однушка, двушка | high | low | **фильтр noindex**. «Визуализация двушки» почти не ищут; «дизайн двушки» — чужой интент (ремонт) |
| Евродвушка | евродвушка, евротрёшка | mid–high | low–mid | **тег**. Не дублировать `kuhnya-gostinaya` |
| Метраж | 30 м², 40, 50, 80, 100+ | mid у журналов | почти нет | **фильтр noindex**. Бакеты на карточке: `≤40 / 40–70 / 70–120 / 120+`. ЧПУ `/40-m2/` — вред |
| Бюджет рендера | недорого, эконом, премиум | mid как «цена» | mid как услуга | **одна** индексная `/ceny` + якоря пакетов. Не `/vizualizaciya/ekonom` × комната |
| Класс жилья | комфорт, бизнес, премиум, элит | mid у новостроек | low | тег объекта, не страница |

Исключение: `/ceny` и формулировки «визуализация от N ₽/м²», «срок кадра» — коммерческое ядро, руками.

Почему не страницы: визуализатору безразлична комнатность для техники кадра; пересечение с «ремонт 2к» каннибализирует и приводит нецелевой трафик; тонкие дубли «современная квартира 60 м²» vs «современная квартира».

## 5. Гео

Визуализация — удалённая услуга (план → рендер). Это не ремонт и не замер на объекте.

### Когда гео имеет смысл

- **Одна** страница города, где студия реально сидит: `/moskva` (или СПб). NAP, люди, как работаем, выезд/не выезд. `LocalBusiness` один раз.
- Коммерческие запросы вида «3д визуализация Москва» — city-level, не район.
- B2B застройщикам города — лучше кейс ЖК на карточке проекта (`city` поле), не городской хаб.

### Когда гео вредно

- Районы, метро, округа («визуализация Хамовники / Приморский»). Спроса нет, паттерн дорвеев.
- Город × комната, город × стиль, город × объект («лофт кухня Казань»). Тонко, шаблон «подставим город».
- Сетка 50–200 городов с одним текстом. Яндекс режет как малоценные / doorway.
- «Область» кроме осмысленного МО/ЛО, если реально рисуете загород.
- `LocalBusiness` в разметке на десятки URL.
- Гео-фильтр портфолио в индексе: работы не привязаны к району заказчика.

Поле `city` у проекта — тег/факт («ЖК в Казани»), не ось ЧПУ.
Поля `district` и `house_series` (П-44Т, И-155, индивидуальная) — **обязательны на карточке** для уникальности и long-tail в тексте. Не ЧПУ в пилоте.

Кластер «кухня П-44Т» — вторая очередь: только Wordstat + ≥8 объектов. Это типология жилья, не гео-дорвей. Район как URL — запрет.

Пилот: **0 или 1** гео-URL. Не плодить.

## 7. Что должно быть индексным / фильтром / тегом

### Обязательный индекс (allowlist)

1. Коммерция: `/`, `/o-studii`, `/uslugi`, `/uslugi/interer`, `/uslugi/eksterier`, `/ceny`, `/kontakty`, `/process`, юр. страницы.
2. Хабы: пилотные стили, комнаты из §1.3, `/eksterier` + must-фасады с кадрами. Не `/obekty`.
3. Белые пары **только** `style × room` из §8.
4. Карточки проектов с паспортом и `indexable=true`. Остальные — каталог без индекса.

### Фильтры `noindex, follow` (ЧПУ не строить)

- любой query каталога: style, room, object, area, rooms, budget, year, sort, page, software;
- 2 фасета, если нет записи `LandingCombo` (если есть — canonical на комбо);
- 3+ фасета всегда;
- метраж, 1к–4к, цена, день/ночь, Corona/V-Ray, год.

### Теги (карточка + чип, без индексного URL)

- все low-комнаты из §1;
- вторичка, дача, таунхаус, апартаменты, кафе;
- евродвушка (пока нет хаба), бакеты м², класс жилья;
- мальчик/девочка, мастер-спальня, гостевой санузел, совмещённый санузел;
- ночь/зима, входная группа, кровля как деталь кадра;
- город проекта;
- софт, число ракурсов.

### Редиректы (не индекс)

зал→гостиная, коридор→прихожая, лоджия→балкон (или наоборот), туалет→санузел/ванная, прачечная→постирочная, коттедж→дом, апартаменты→квартира, контемпорари→современный, сканди→скандинавский, веранда→терраса, open-space квартиры→кухня-гостиная.

| gostinaya | loft, sovremennyj, klassika, minimalizm, ar-deko, neoklassika |

Прихожая, кабинет, гардеробная, балкон — **хабы без style×room** на старте. Комбо после спроса.

**style × object — не создаём.** Квартира закрыта хабом стиля. Дом/фасад — `/uslugi/vizualizaciya-doma` и `/eksterier/{style}`. Барнхаус и шале не живут в `/stili/.../dom`.

**Не индексируем:** object × room, style × room × object, geo × что угодно, area × что угодно.

### 8.2 Опасные комбинации (тонкий / дубль)

Не создавать ЧПУ. Если пользователь ставит фильтр — noindex или схлопнуть на предка.

| Сетка городов × любые фасеты | Малоценные | одна гео-страница максимум |

### 8.3 Матрица решений (кратко)

```
комната high + стиль must + ≥6 кадров     → INDEX комбо
комната mid  + стиль                      → хаб комнаты INDEX; комбо позже
комната low  + что угодно                 → TAG
объект квартира/дом + стиль               → НЕ URL (хаб стиля / услуга / экстерьер)
объект × комната                          → NOINDEX / не создавать
стиль × комната × объект                  → ЗАПРЕТ
м² / 1к–4к / бюджет                       → FILTER noindex; цены — одна страница
город                                     → 0–1 INDEX; район — ЗАПРЕТ
экстерьер зона (фасад, участок)           → INDEX хаб; × интерьерная комната — ЗАПРЕТ
синоним с спросом                         → 301, не index
```

## 9. Пилот vs масштаб

Пилот (совпадает с `ARCHITECTURE.md` / `PLAN.md`): 8–12 хабов комнат+объектов+экстерьера, must-стили, 15–25 белых комбо, 20–40 проектов. Полный декарт 16×20 комнат не цель.

После пробивки Wordstat можно: поднять `sanuzel` / `stolovaya` / `taunhaus` / `evrodvushka` в хабы; свапнуть `balkon`↔`lodzhiya`; схлопнуть `sanuzel`→`vannaya`, если частота не держит.

Частотности в этом файле — гипотеза тиров, не замер. Комбо без пробивки не публиковать.
