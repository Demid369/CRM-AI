# Сигнификация — архитектура сайта

Студия 3D-визуализации интерьеров и экстерьеров. Цель: programmatic SEO на повторяющихся паттернах запросов + генератор картинок как лидмагнит. Сейчас фиксируем архитектуру, не вёрстку.

Имя репозитория на GitHub пока `CRM-AI`. Сайт в проде — отдельный slug, не `crm-ai`.

## 1. Что продаём на самом деле

Не «ещё один Midjourney». Продукт — визуализация под ключ: планировка → ракурсы → правки → финальные кадры для согласования с заказчиком.

Генератор на сайте — превью и крючок. Деньги: заказ студии и пакеты доработки. Если подписка на генерации станет дешёвым безлимитом, мы конкурируем с Flux, а не с дизайн-студиями. Подписка — до ent, не ядро оффера.

## 2. Жёсткие правила pSEO (из практики + Toolfox)

Яндекс режет шаблон сильнее Google. «1 000 страниц → топ» без данных — фильтр, не стратегия.

- Страница существует только если есть спрос **и** уникальные данные (свои рендеры + поля, которых нет у соседа).
- В индексе: хабы и белый список комбинаций. Остальные фильтры — `noindex, follow` или query без ЧПУ.
- Не публиковать всё сразу. Пилот → метрики → волны.
- 70% уникальности — не синонимайз. Это доля **уникальных блоков данных** на странице (рендеры, метрики объекта, решения, палитра, FAQ кластера). Общий каркас 10–15%.
- Нет данных — нет URL. Пустую комбинацию не создаём.
- Раз в квартал вырезать страницы без трафика и без охвата.

Пилот: 40–80 URL, не 1 000.

## 3. Карта сайта: четыре слоя, не каша

```
Коммерческое ядро          Хабы (индекс)
/                          /stili
/o-studii                  /stili/{style}
/uslugi                    /komnaty
/uslugi/{slug}             /komnaty/{room}
/ceny                      /eksterier
/kontakty                  /eksterier/{style}
/process                   /obekty/{object}          # квартира, дом, офис

Белый список посадочных     Каталог и карточки
/stili/{style}/{room}       /raboty                  # фильтры = ?query, noindex
/stili/{style}/{object}     /raboty/{project}        # уникальный проект
                            /lk/*                    # noindex
                            /legal/*                 # index политика, оферта
```

Один канонический путь на интент. «Кухня в стиле лофт» живёт **только** в `/stili/loft/kuhnya`. Каталог `?style=loft&room=kuhnya` каноникалит туда, если посадочная есть; иначе `noindex`.

Не делаем `/stili/loft/kuhnya/kvartira`. Тройные фасеты — тонкий контент и каннибализация.

Сравнения стилей (`/sravneniya/loft-vs-skandi`) — вторая очередь, не пилот.

Блог — не pSEO. 8–15 экспертных опор (процесс, сроки, бриф, ошибки заказчика). Их пишем вручную.

## 5. Таксономия: оси, не бесконечный декартов продукт

Полный справочник — `docs/taxonomy.md`. Здесь правила.

**Индексируем оси по отдельности и только белые пары.** Не `16 стилей × 12 комнат × 6 объектов × 10 городов`.

Канон стилей интерьера (хабы): современный, минимализм, скандинавский, лофт, классика, неоклассика, прованс, ар-деко, джапанди, хай-тек, эко, бохо, средиземноморский, mid-century, английский, американская классика.

Синонимы не получают URL: контемпорари → современный, зал → гостиная, санузел → ванная (если нет отдельного спроса на «санузел в стиле X»), кантри/рустик — один хаб или second-tier.

Second-tier (хаб только после Wordstat): ваби-саби, барнхаус-интерьер, шале-интерьер, модерн. Барокко, фьюжн, «евроремонт как стиль» — теги, не хабы.

Экстерьер — своё дерево: современный фасад, минимализм, шале, барнхаус, хай-тек, классика, средиземноморский, фахверк, скандинавский.

Комнаты-хабы (пилот): кухня, кухня-гостиная, гостиная, спальня, детская, ванная, прихожая, кабинет, гардеробная, балкон. Зал→гостиная, лоджия→балкон, коридор→прихожая, туалет→санузел/ванная. Санузел — второй хаб только после Wordstat, иначе 301 на ванную. Столовая / open space / постирочная — теги.

Объекты для комбо: квартира, дом, студия. Офис, ресторан, ритейл, отель — услуги, не ось pSEO. Вторичка, дача, апартаменты, коттедж — теги/редиректы на квартиру или дом. Метраж, 1к–4к, бюджет — фильтры noindex; цены — одна страница.

Гео-страницы («визуализация в Москве») — одна, если студия реально там. Сотни городов без локальных фактов = дорвеи. Районы, метро, город×комната — не делаем.

Ориентир на 1 000 индексных URL (после пилота, не в день запуска):

| Слой | Число | Откуда |
| --- | --- | --- |
| Коммерция + юр. | 12–15 | руками |
| Хабы стилей + комнат + экстерьера + объектов | 40–50 | канон |
| Белые комбо стиль×комната | 80–140 | Wordstat, не декарт |
| Белые комбо стиль×объект | 20–40 | только квартира/дом × must-стили |
| Карточки проектов | 600–800 | уникальные работы |
| **Итого** | **~750–1 050** | пустые комбо вырезаем |

Карточка проекта — главный вклад в «1 000». Комбо без 4+ своих рендеров не публикуем.

## 6. Модель данных (страница = запись, не HTML-файл)

Каждый индексный URL — сущность в CMS/БД. Генератор HTML только читает.

```
Style          slug, name, aliases[], tier, palette[], materials[],
               do[], dont[], lighting, furniture, text_unique, faq[]

Room           slug, name, aliases[], tier

ObjectType     slug, name, aliases[]   # kvartira, dom, fasad

Project        slug, title, style_id, room_ids[], object_id,
               area_m2, year, software[], city?,
               district?, house_series?,   # поля, НЕ ось URL. П-44Т / Кузьминки — уникальность и long-tail
               brief, decisions[], palette[], materials[],
               images[] (own renders), plan_image?,
               related_ids[], indexable, published_at

LandingCombo   style_id + room_id XOR object_id,
               wordstat_freq, unique_intro, unique_tips[],
               faq[], project_ids[] (min 4), index_policy

GenerationJob  user/session, page_context, prompt, plan_asset,
               status, output_urls[], watermarked, credits_spent

Lead           phone, consent_at, source_url, style, room, jobs[]

CreditLedger   account, delta, reason, created_at
```

Уникальность 70% проверяем полями, не «прогоном text.ru после синонимайза»:

- свои изображения (обязательно);
- `brief` / `decisions` / `palette` / `materials` уникальны у проекта;
- у комбо — свой intro и 4+ привязанных проекта, иначе `draft`.

Контент комбо пишем мы (как договорились). Шаблон не дописывает воду.

## 7. Перелинковка

- Хаб стиля → все белые комнаты этого стиля + 8–12 проектов + 2 соседних стиля.
- Комбо → хаб стиля, хаб комнаты, 6 соседних комбо (другие комнаты того же стиля + тот же room в соседнем стиле), 6–12 проектов.
- Проект → стиль, комнаты, 3 соседних проекта, 1 комбо.
- Коммерческие страницы ссылаются на 6–8 сильных хабов, не на все 1 000.
- Хлебные крошки + BreadcrumbList.
- Sitemap: чанки по типу. Генерации и ЛК не попадают.

## 8. Генератор — виджет, не контент страницы

Контекст страницы (стиль, комната) идёт в промпт. Результат не индексируется и не становится URL.

Виджет только на главной, услугах, хабах и белых комбо. Не на `/legal/*`, `/kontakty`, `/ceny`. Не на всех 1000 в первый день — сначала 2–3 шаблона. Ниже уникального контента, не main entity. Schema `SoftwareApplication` — только если заведём `/generator`.

Бриф «2 + 6 и полный файл после телефона» отвергнут: SEO-трафик сожжёт GPU, полный кадр за номер убивает заявку.

### Воронка кредитов

| Состояние | Кредиты | Что можно |
| --- | --- | --- |
| Аноним | 1 / 30 дней | квиз или короткий промпт; водяной знак; ≤1024; без download |
| Телефон + OTP | +2, сгорают за 14 дней | история в ЛК, знак **остаётся**, merge гостевого job |
| Пакет 20/50 | только в ЛК после лимита | полный файл, без знака. Не на `/ceny` студии |
| Заявка студии | 0, отдельный поток | человек, счёт, договор. Превью = референс, не ТЗ |

Вес: текст/квиз = 1, планировка (img2img) = 3. Один job = один кадр. Fail провайдера кредит не жжёт.

После 1-й генерации сразу два CTA: «просчёт студии» и «ещё превью — телефон». Кредитная модалка ≠ заявка. Согласия разные: аккаунт, контакт студии, реклама, трансграничка GPU.

Потолок: ≤4 бесплатных кадра на `phone_e164` / 30 дней, включая смерженные гостевые. Один телефон — один ledger. Удалил аккаунт — номер в блоклисте грантов.

Пакеты не в коммерческом ядре. «Человеческий тариф» в кредитах не заводим. Telegram — поле в заявке, не Login.

### Антиабьюз и API

- Квота гостя: signed httpOnly `guest_id` + мягкий `ip_hash`. Fingerprint не собираем.
- Лок квоты до enqueue, `idempotency_key`. Капча со 2-й генерации и всегда на OTP.
- OTP: согласие до отправки SMS. 3/телефон/сутки, 5/IP/час. Поручение шлюзу. Не-RU — только явным решением. Стоп-лист виртуальных номеров.
- Дневной `gpu_budget`: 80% — стоп гостей; 100% — стоп всех кроме заявки студии. Гостю дешёвая модель.
- Планировка: MIME/size, не публичный CDN, TTL 30 дней, «имею право», не в training, strip EXIF.
- `GET /jobs/:id/download` — 402 без `paid | studio_contract`.
- Гостевые job мержатся в ЛК атомарно, квота не удваивается.
- User-gen в каталог в v1 не публикуем.

Интерьер по плану ≈ $0.04–0.20 за удачный кадр. Юнит до кода: `$/текст`, `$/план`, ₽ SMS, визит→ген→OTP→заявка→счёт. Если `trial_cost × tryers > 0.3 × чек × CR` — виджет уже, не шире.

### Чтобы не убить SEO / CWV

- Остров: `import()` по idle / IO / click. SSR без модели и WebGL.
- `/api/generate` за капчей/сессией, ключ на бэке, `noindex`.
- Результат: `/lk/jobs/{id}`, не sitemap.
- Дисклеймер в виджете: ИИ-превью ≠ рендер студии.
- Не обещать в H1 «магия по планировке».

## 9. Юридика и доверие (обязательный минимум)

Политика в футере — не контур. Жёсткий разбор: `docs/architecture-audit.md`.

- Уведомление в РКН как оператор (ст. 22) **до** первого телефона.
- Политика + оферта + отдельное согласие. Чекбокс пустой. Лог: timestamp, IP, UA, версия текста, id формы.
- С 01.09.2025 нельзя склеивать ПДн + рекламу/звонок/SMS в один чекбокс (38-ФЗ ст. 18). OTP — транзакционное; «мы перезвоним» — реклама, отдельное согласие.
- **Локализация 152-ФЗ (с 01.07.2025):** первичный сбор/запись ПДн граждан РФ — на серверах в РФ. Аккаунты не в Supabase EU / Vercel KV / US S3 как единственном сторе.
- Трансграничка (fal.ai / Replicate / GA4): отдельное согласие + уведомление РКН **до** передачи. Планировка = потенциальный адрес/серия дома — в цели обработки явно. Штрафы юрлицу до 6 / 18 млн.
- Хостинг ПДн и ЛК: РФ (Selectel / Yandex Cloud / контур t9). GPU за рубежом — только как обработчик с ДПДн и оформленной ТППДн, либо свой GPU в РФ.
- Планировки: срок хранения, удаление по запросу, strip EXIF GPS либо явное согласие на гео.
- 54-ФЗ на подписку/пакеты: чек (ЮKassa «Чеки» или своя касса), оферта, автопродление, отмена в 1 клик.
- Реквизиты и контакты на `/o-studii` и в подвале. Дисклеймер: ИИ-превью ≠ финальный рендер.
- Рендеры студии vs витринные нейрокадры — флаг `origin: studio | campaign`. Не мешать в одном списке.

## 10. Стек (чтобы потом не переписывать URL)

- Публичные страницы: SSG (Astro или Next.js). 1 000 URL должны быть файлами/пререндером, не SSR из пустой CMS на каждый хит.
- CMS: Postgres + админка (Payload или своя тонкая). Не Google Sheets в проде.
- Генерации: очередь (Redis + worker), провайдер картинок за адаптером (`ImageGenProvider`).
- Auth: Telegram Login **или** OTP (SMS.ru / smsc) **или** email. Сессия. ЛК — те же origin, `noindex`.
- Метрика: Яндекс.Метрика по умолчанию. GA4 — только после согласия и с пониманием трансгранички.
- Картинки портфолио: AVIF/WebP, srcset, свой CDN/nginx, image sitemap.
- Поиск/мониторинг: Вебмастер + GSC + Topvisor/Rush на белый список URL, не на «все query».
- Хост: один из сайтов на t9, порт и slug — по `/home/user1/apps/ARCHITECTURE.md` на сервере, не наугад.

Схема: `Organization` + `Offer` на услугах, `ImageObject` на проектах, `FAQPage` на хабах/комбо, `BreadcrumbList` везде. Не `LocalBusiness` в 80 городах.

## 11. Что в исходном брифе было слабо и как усилили

1. **Декарт фильтров в индекс** — заменён белым списком и раздельными шаблонами.
2. **1 000 URL день в день** — пилот, потом волны, потом вырезание.
3. **70% уникальности без модели данных** — уникальность = заполненные поля + свои кадры.
4. **Генератор как ядро** — генератор как лидмагнит, оффер студии на каждой странице.
5. **Экстерьер потерялся бы в «комнатах»** — отдельное дерево.
6. **Гео не оговорено** — максимум одна локальная страница.
7. **Нет коммерческого ядра** — услуги, цены, процесс, контакты обязательны до массы pSEO.
8. **Телефон без 152-ФЗ и антиабьюза** — OTP с лимитами, раздельные согласия, один ledger на номер.
9. **Каннибализация** «лофт» vs «кухня лофт» vs карточка проекта — разные шаблоны и одна каноника.
10. **Нет прунинга** — страница без данных или без спроса не живёт в индексе.
11. **Витрина из одной нейросети** без живых кейсов — слабый E-E-A-T. В первую волну кладём реальные работы, даже если их 20.
12. **2+6 и полный файл за номер** — отвергнуто: 1+1, знак не снимается, download только пакет/договор.
13. **Подписка на `/ceny`** — пакеты только в ЛК, не рядом с договором студии.

## 12. Публикация, robots, гейт качества

`robots.txt`: закрыть `/lk`, `/api`, query-строки каталога не отдаём в sitemap. Не закрывать ЧПУ комбо.

Sitemap: `sitemap-core.xml`, `sitemap-hubs.xml`, `sitemap-combos.xml`, `sitemap-projects.xml`, `sitemap-images.xml`. Новый URL в индекс — только из волны, не «все draft разом».

Гейт перед `published`:

- есть кластер и частотность (комбо) или уникальный проект;
- ≥4 своих кадра (комбо) / ≥3 (проект);
- заполнены уникальные поля (не общий абзац);
- внутренние ссылки на родителя и 3 соседа;
- одна H1, уникальные title/description;
- `origin` кадра проставлен;
- для комбо нет второй каноники в каталоге.

70% считаем **двумя** гейтами (не Advego «vs интернет» как единственная цифра):

1. **Данные.** Доля символов в уникальных полях + подписи к кадрам / смысловое тело (минус навигация и виджет) ≥ 0.70. Минимум 6 из 10 полей проекта реально разные у соседа (метраж, район, серия дома, год, задача, ограничения, материалы, ошибка, свои pHash-кадры, связи).
2. **Семантика.** Эмбеддинги смыслового тела (multilingual-e5 / rubert): max cosine с сиблингами того же шаблона < 0.72. Иначе `draft`.
3. Картинки: pHash без коллизий со стоком и другими карточками.

Если ниже — не публикуем, не «докручиваем водой». CI до `published`.

Редиректы синонимов: `zal`→`gostinaya`, `sovremennyj`←`contemporary`/`kontemporari`, `art-deco`→`ar-deko`. Одна карта в CMS, 301 навсегда.

## 13. Критерий «архитектура готова»

- Любой будущий URL объясняется таблицей типов и правилом индекса.
- Любая комбинация либо в белом списке, либо не существует как ЧПУ.
- Генератор можно выключить — сайт остаётся полноценной студией.
- Пилот считается в десятках URL, не в тысячах.
- Юридика и ЛК не блокируют запуск витрины: виджет можно прикрутить второй очередью.

Детализация осей: `docs/taxonomy.md`. Порядок работ: `docs/PLAN.md`. Жёсткий аудит пробелов (юридика, GPU, воронка, CWV): `docs/architecture-audit.md`.
