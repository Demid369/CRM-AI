# Сигнификация: аудит архитектуры (programmatic SEO + ИИ-генератор)

Жёсткий разбор перед разработкой. Принцип programmatic SEO: **шаблон + уникальные данные + уникальный смысл + внутренние связи**. Не 1000 клонов. Не doorway.

Продукт в брифе: главная / о компании / каталог, хабы стилей, ~1000 портфолио, фильтры стиль×комната, генератор на **всех** страницах (2 бесплатно → телефон+ЛК → 6 → подписка). Рынок: Россия. Поиск: Яндекс **и** Google, не «потом Яндекс».

---

## 0. Главный стратегический риск (не SEO)

Вы смешиваете **два разных бизнеса** на одном домене и одной воронке:

| | Студия 3D-визуализации | SaaS-генератор картинок |
|---|---|---|
| Клиент | застройщик, дизайнер, частник с бюджетом 80–500+ тыс. | человек, которому «красиво и бесплатно» |
| Цикл сделки | дни–недели, бриф, правки, счёт | секунды, карта / подписка |
| Юнит-экономика | маржа на часах команды | маржа на GPU минус абьюз |
| SEO-интент | «визуализация кухни лофт цена / портфолио» | «нейросеть интерьер бесплатно» |

1000 портфолио-страниц кормят **студию**. Генератор на каждой странице кормит **абьюзеров и «бесплатный Midjourney»**. Телефон после 2 генераций отсекает платёжеспособных B2B и оставляет виртуальные SIM.

Если ядро — продажа визуализаций: генератор = лид-магнит с жёстким капом, водяным знаком, низким разрешением, **не** SaaS. Если ядро — подписка: не плодите 1000 «портфолио», это другой сайт и другой интент.

Дальше — как не убить оба сразу.

## 1. Что владелец почти наверняка упустил

### 1.1. Юридика ПДн / 152-ФЗ (не «политика в футере»)

Обязательный минимум **до** первого телефона и первой планировки:

1. Уведомление в Роскомнадзор как оператор ПДн (ст. 22). Штраф за отсутствие — отдельно, с 2025.
2. Политика + оферта + отдельное согласие на ПДн. Чекбокс **пустой**, не pre-checked.
3. Лог согласия: timestamp, IP, UA, версия текста, id формы. Без лога согласия нет.
4. С 01.09.2025 нельзя склеивать в один чекбокс: ПДн + реклама + рассылка. Минимум два: «обработка ПДн» и «реклама/звонок/SMS» (38-ФЗ ст. 18). OTP — транзакционное; любой «мы вам перезвоним / акция» — реклама.
5. **Локализация.** С 01.07.2025 первичный сбор/запись/систематизация ПДн граждан РФ — на серверах в РФ. Потом можно трансграничку, но: отдельное согласие + уведомление РКН **до** передачи. Штрафы юрлицу: до 6 млн / повторно до 18 млн.
6. Что ломает схему «Vercel + Supabase EU + fal.ai/Replicate US + GA4»:
   - аккаунт (телефон, email) в зарубежной БД = нарушение локализации;
   - промпт + планировка на US GPU = трансграничка (планировка часто содержит адрес, серию дома, ФИО на штампе);
   - GA4, Cloudflare logs, Intercom, Mixpanel — тоже трансграничка.
7. Планировка — не «просто картинка». Это потенциально адрес, состав семьи, планировка квартиры. Срок хранения, цель, удаление по запросу — в политике явно.
8. Cookies: Метрика — ок для РФ; GA4 — только после согласия и с пониманием трансгранички. По умолчанию: Яндекс.Метрика + серверные логи в РФ.
9. Право субъекта: выгрузка, удаление, отзыв. Кнопка в ЛК, не «напишите на info@».
10. Поручение обработчику (ДПДн) с хостером, SMS-провайдером, GPU-подрядчиком. Если GPU в РФ нет — в политике список стран и юрлиц.

Это не «потом юрист нарисует PDF». Это схема данных и выбор хостинга на старте.

### 1.2. SMS / телефон как ключ ЛК

- OTP ≠ согласие на обработку и тем более на рекламу.
- Стоимость SMS в РФ: ориентир 3–7 ₽/шт. Абъюз: бомбардировка чужих номеров с вашей формы = деньги + жалобы оператору + блок имени отправителя.
- Защита OTP: rate-limit по IP/ASN/устройству, captcha после 2-й попытки, TTL 5 мин, 3 попытки ввода, не логировать сам код.
- Телефон ≠ личность. sms-activate / virtual SIM / eSIM-фермы. Один человек = 50 «аккаунтов» × 8 бесплатных генераций.
- Звонок менеджера на номер, полученный «за генерации», без отдельного согласия на рекламу — классика жалобы в УФАС.

### 1.3. Себестоимость GPU (не «копейки на картинку»)

Публичные API (fal / Replicate, 2026): SDXL ~$0.003–0.006; Flux Dev ~$0.025; Flux Pro ~$0.05. Это **txt2img 1024**. Вам нужен интерьер:

- img2img / ControlNet / depth / канни / «по планировке» = 2–5 прогонов или тяжёлая модель;
- реальный чек качества «чтобы не стыдно рядом с портфолио»: **$0.04–0.20 за удачный кадр**, не за клик;
- пользователь жмёт «ещё» 3–5 раз, шлёт мусор, шлёт NSFW, шлёт 8K.

Грубая дыра в юнит-экономике (честный трафик, без ботов):

- 1000 страниц × 80 визитов/мес × 4% жмут генерацию = 3 200 сессий;
- × 2 бесплатных × $0.08 = **~$500/мес только «2 бесплатно»**;
- 15% доходят до телефона × 6 генераций = ещё ~$230;
- абьюз ×5–20 (прокси, фермы, «бесплатный Midjourney») = **$3–10к/мес** ещё до первой подписки.

Плюс очередь, ретраи, хранение исходников и PNG, CDN, модерация. Подписка 990–1990 ₽ не спасёт, если 8 бесплатных съедают маржу.

Свой GPU (A10 / L40S в Selectel / Yandex Cloud): дешевле на объёме, но это девопс, простой, охрана очереди, и ПДн/картинки всё равно в РФ. Заложить **до** вёрстки лендинга.

### 1.4. Абъюз генераций (дырявый «2 + 6»)

Что сломает схему за неделю после Хабра/Telegram:

- инкогнито / чистка cookie / другой браузер = новые 2;
- смена IP (мобильный CGNAT, VPN);
- много устройств в офисе = один Wi-Fi, но разные fingerprint;
- прогон одной планировки как «бесплатный рендер-ферма»;
- API-скрейп виджета, если генерация торчит с фронта с ключом;
- генерация чужих брендов / порно / чужих квартир по украденной планировке.

Минимум, иначе вы спонсор чужого SaaS:

- лимит на **сервере**: fingerprint + IP + CIDR + device, не localStorage;
- 2 бесплатных на **устройство+IP за 30 дней**, не на вкладку;
- после телефона — лимит на **нормализованный номер** (и на паспортные/карту, когда дойдёт до оплаты);
- очередь + капча до **первой** генерации, не после;
- водяной знак + max 1024 + сжатие на бесплатных;
- запрет скачивания без аккаунта / только preview;
- контент-фильтр + отказ по пустому/инжекционному промпту;
- ключ API только на бэкенде, signed upload, virus scan планировок;
- алерты: >N генераций с одной ASN, всплеск 3 ночи, одинаковый hash планировки.

### 1.5. Каннибализация SEO

Типичный взрыв, если сделать «как в голове»:

- `/stili/loft` и `/portfolio?style=loft` и 80 карточек «квартира в стиле лофт» бьются за один запрос;
- `/stili/loft/kuhnya` = `/portfolio/kuhnya-loft-na-taganke` = услуга «визуализация кухни»;
- title у 200 страниц: «Дизайн кухни в стиле лофт — примеры». Яндекс схлопнет в МПК.

Правило одно: **один URL — один интент, который сосед не закрывает лучше**. Если человек не может сказать, какая из двух страниц должна быть в топе — алгоритму тоже нельзя.

Иерархия интентов (жёстко развести):

| Уровень | Интент | Кто побеждает |
|---|---|---|
| Услуга | «заказать 3D-визуализацию кухни» | `/uslugi/...` |
| Хаб стиля | «что такое лофт в интерьере + подборка работ» | `/stili/loft` |
| Кластер стиль×комната | «кухня в стиле лофт — приёмы и 12 работ» | `/stili/loft/kuhnya` **только если** есть спрос **и** ≥8–12 работ **и** уникальный текст |
| Лист | «конкретный объект: 54 м², П-44Т, Кузьминки, 2025» | `/portfolio/[slug]` |

Листья **не** таргетят «кухня лофт». Они таргетят уникальный объект + long-tail (район, серия дома, метраж).

### 1.6. Thin content / МПК / doorway

1000 страниц с 3 абзацами «Лофт — это кирпич и металл…» + 6 картинок = учебник по фильтру малополезного контента. Яндекс снимает **шаблон пачками**, не по одной URL.

Doorway — это не только дорвеи 2012. Это ещё:

- страницы, которые существуют, чтобы перекинуть на генератор/телефон;
- комбинации фильтров без своего смысла;
- «уникальный» GPT-текст, который не опирается на факты объекта.

### 1.7. «70% уникальный контент» — как мерить, а не как врать себе

«70%» без методики — самообман. Нужны **три** метрики, гейт в CI **до** публикации:

**A. Межстраничная уникальность шаблона (то, что обычно имеют в виду)**

- Режете страницу на блоки: hero, факты, тело, FAQ, CTA, генератор.
- Boilerplate (навигация, футер, одинаковый CTA, виджет генератора) **не входит** в знаменатель уникальности.
- По «смысловому телу»: эмбеддинги (multilingual-e5 / rubert) → косинус со всеми сиблингами того же шаблона.
- Гейт: max cosine < 0.72 (или Jaccard шинглов 5–6 < 0.35). Иначе `noindex` или не публиковать.
- «70% уникально» = доля токенов смыслового тела, которые не повторяются в ближайшем соседе, ≥ 0.70. Это **не** Advego vs интернет.

**B. Уникальность vs корпус интернета**

- Выборочный Advego/text.ru на 5–10% выборки + ручная проверка фактов.
- Картинки: pHash/dHash, коллизии с другими карточками и стоками = бан публикации.

**C. Уникальность данными, не прилагательными**

Страница не проходит гейт, если не заполнены минимум **6 из 10** полей, и они реально разные:

1. тип объекта + метраж;
2. район / город;
3. серия дома или тип планировки (П-44, индивидуальная, таунхаус) — **это золото РФ, его нет в брифе**;
4. год и срок;
5. задача клиента (1 факт, не «сделать красиво»);
6. ограничения (несущая, мокрые зоны, бюджет);
7. 3–7 конкретных материалов/позиций (не «натуральное дерево»);
8. 1 ошибка, которой избежали;
9. 4+ своих рендера/фото с уникальным pHash;
10. связанность: 3 соседних проекта + родительский хаб.

Текст 400–800 слов **из этих полей**, не GPT «о философии лофта». Хаб стиля — ручной, 4–8 тыс. знаков. Кластер стиль×комната — ручной каркас + автоподстановка работ.

Без гейта «70%» = 1000 страниц с перестановкой синонимов.

### 1.8. Индексация фильтров

`стиль × комната` — **не фильтр каталога**, а **заранее отобранные кластеры**.

Открывать в индекс:

- только пары из семантики (Wordstat + GSC/Вебмастер + ручной отсев);
- только если объектов ≥ порога (8–12) **или** текст кластера самодостаточен без сетки;
- статичный URL, уникальные title/h1/intro/FAQ.

Закрывать:

- любые `?sort=`, `?page=`, `?q=`;
- тройные пересечения (лофт × кухня × серый × 30 м²);
- пустые и «1–2 работы»;
- клиентский JS-фильтр каталога: **без смены индексного URL** (AJAX). Либо `noindex,follow` + canonical на хаб.

Яндекс.Вебмастер → «Параметры URL». Sitemap — только канонические. Внутренние ссылки — только на открытые кластеры, не на query-string.

Иначе 8 стилей × 10 комнат × сортировки = сотни тонких URL и сгоревший crawl budget на 1000 листьях.

### 1.9. Sitemap / роботы / пагинация

- `sitemap-index.xml` → `sitemap-pages.xml`, `sitemap-stili.xml`, `sitemap-clusters.xml`, `sitemap-portfolio.xml` (чанки по 200–500).
- Только 200 + canonical self + indexable. Без ЛК, без `?`, без 301.
- Честный `lastmod` (дата объекта / дата текста), не now() при деплое.
- `robots.txt`: Disallow `/lk`, `/api`, `/search`, параметры. Не закрывать CSS/JS.
- Пагинация каталога: либо `noindex` на page>1, либо load-more без URL. Не плодить `/portfolio/page/47` в индекс.
- Генерации пользователей: **никогда** не попадают в sitemap и в HTML, который индексируется.

### 1.10. Schema — по типу страницы, не «всё сразу»

| Тип | Schema | Не делать |
|---|---|---|
| Главная / студия | `LocalBusiness` или `ProfessionalService` (адрес, телефон, geo, areaServed) | фейковый AggregateRating |
| Услуга | `Service` + `Offer` (цена «от», если правда) | Product на услугу без оферты |
| Хаб / кластер | `CollectionPage` + `BreadcrumbList` + `FAQPage` только на видимые FAQ | FAQ, которого нет на странице |
| Портфолио | `CreativeWork` / `VisualArtwork` / `ImageGallery`: name, dateCreated, location, image[], about (стиль, комната) | Review на свои же работы |
| Генератор (одна посадочная) | `SoftwareApplication` или `WebApplication` | SoftwareApplication на каждой из 1000 |
| Навигация | `BreadcrumbList` везде | |

Яндекс берёт не всё. Валидировать: Rich Results + инструмент Вебмастера. Врать в schema = ручной риск, не «плюс к топу».

### 1.11. Ещё слепые зоны вне брифа

- **CWV картинок:** 1000 страниц × 8 рендеров 4K JPEG = LCP 4–8 с и смерть мобильного топа. Нужны AVIF/WebP, ресайз, 1× priority LCP, остальные lazy, правильный `sizes`, blur placeholder, фиксированный aspect-ratio.
- **Авторские права:** рендеры фрилансеров, чужие текстуры, бренды мебели в кадре, планировки заказчика. Договор + модель лицензии на сайте.
- **54-ФЗ:** подписка = чек. ЮKassa «Чеки» или своя касса. Оферта, НДС, автопродление, отмена в 1 клик, возврат по закону о защите прав потребителей (цифровая услуга).
- **Маркировка рекламы:** свой сайт — обычно не ОРД; таргет/посевы/блоггеры — да. SMS-реклама — согласие, не erid.
- **Хостинг и персональные кабинеты в РФ.** Selectel / Yandex Cloud / Timeweb Cloud, не «Vercel + US S3» как единственный стор аккаунтов.
- **Оферта + реквизиты + политика** — коммерческие страницы, не приложения. Без этого Яндекс и реклама сомневаются, ФАС — нет.
- **E-E-A-T студии:** живые люди, адрес, ИНН, реальные объекты с датами. Анонимный «мы делаем 3D» + 1000 шаблонных страниц = нулевой trust.

## 2. Генератор на SEO-странице: не убить CWV и не словить спам-сигнал

### 2.1. Спам-сигнал

Поисковик видит 1000 URL с **одинаковым** блоком «Сгенерируй интерьер ИИ» на первом экране, одинаковым H2 и формой. Это:

- шаблонный junk выше уникального смысла;
- страница «для инструмента», а не для запроса;
- риск, что сгенерированные картинки/тексты попадают в индекс (тонкий AI-контент).

Правила:

1. Генератор **ниже** уникального контента (после фактов, галереи, 2–3 абзацев по объекту). На листьях — после галереи. На хабах — после подборки.
2. Заголовок виджета **зависит от страницы**: «Собрать вариант кухни 12 м² в лофте как в этом проекте», не глобальный H2.
3. Виджет не в `<main>` как main entity. Основная сущность страницы — объект/хаб. В schema генератора на листьях нет.
4. HTML виджета для бота: заголовок + 2 предложения + ссылка на `/generator`. Тяжёлая форма — после жеста или idle.
5. Результат генерации: `noindex`, не в DOM при SSR, не в sitemap, URL вида `/lk/jobs/[id]`.
6. Не клоакинг: бот и пользователь видят один и тот же уникальный контент; отличается только гидратация формы.
7. Не подменять тексты страницы сгенерированным описанием.

### 2.2. CWV (LCP / INP / CLS)

Генератор на **всех** страницах в initial JS = провал INP.

Архитектура виджета:

```
SSR/SSG страницы: 0 KB кода модели, 0 KB редактора промпта
  → island: кнопка + 1 LCP-картинка объекта
  → import() по requestIdleCallback / IntersectionObserver / click
  → форма: промпт (prefill из контекста страницы) + upload
  → POST /api/generate (очередь)
  → поллинг job, картинка с резервом aspect-ratio
```

Жёстко:

- **Один** `priority` image на страницу — hero объекта, не UI генератора.
- `sizes` по факту вёрстки. Без `sizes` карточка 400 px качает 3840.
- Галерея: 1–2 кадра above the fold, дальше lazy + виртуализация после 8–12.
- Виджет: зарезервированная высота (CLS), скелетон очереди.
- Никакого TensorFlow/ONNX в браузере. Никакого чата, pixel-perfect редактора, Three.js в initial bundle.
- Аналитика: Метрика `lazyOnload`, не в head гонкой с LCP.
- Префетч GPU-виджета — нет. Prefetch `/generator` — да, по hover.
- Страницы портфолио: SSG/ISR. Генератор не делает страницу dynamic.

Отдельный маршрут `/generator` — единственное место, где инструмент может быть above the fold. Это коммерческо-инструментальная страница, не 1000 клонов.

### 2.3. Контекст страницы → промпт (единственная польза виджета на SEO-URL)

Prefill, не «ещё одна форма»:

- лист: стиль, комната, метраж, 1–2 материала, «как на фото 2»;
- кластер: стиль + комната;
- хаб: только стиль;
- услуга: без привязки к объекту, акцент «загрузить планировку → расчёт».

Загрузка планировки на листе чужого объекта — нормально (лид). Не подмешивать планировку пользователя в индекс.

## 3. Воронка 2 → телефон → 6 → подписка

### 3.1. Дыры

1. **Неверный обмен.** Отдаёте ценность (картинки) **до** контакта. После 2 удачных кадра мотивация оставить телефон падает, не растёт.
2. **Телефон как стена** режет B2B (корп. почта, Telegram) и тех, кто не хочет звонка в 21:00.
3. **6 после регистрации** — подарок абьюзеру. Для лида студии хватит 1 превью в ЛК.
4. **Подписка конкурирует с основной услугой.** «Зачем платить 150 тыс. за визуализацию, если подписка 1 490». Либо тарифы честно разные (превью vs производство), либо подписки нет.
5. **Качество 2 бесплатных.** Если плохо — бренд студии в мусор. Если хорошо — вы GPU-благотворитель.
6. **Нет квалификации.** Неизвестно: квартира / ЖК / застройщик / «просто поиграться».
7. **Нет пути в сделку.** После телефона должен быть сценарий (квиз / слот / файл), не «менеджер когда-нибудь позвонит».
8. **Мошенничество:** украденные карты на подписке, chargeback, перепродажа слотов, генерация по чужим планировкам, OTP-бомбинг, пайплайн «ваш сайт = бесплатный ComfyUI».

### 3.2. Как закрыть (минимум)

- Бесплатно: **1** превью, водяной знак, 1024, без 4K, без пакета ракурсов.
- Капча + серверный лимит до генерации.
- Контакт **до** скачивания, не до первой кнопки: посмотреть на сайте можно, забрать — нет.
- Телефон **или** Telegram **или** email. Для РФ Telegram сильнее телефона: номер уже верифицирован TG, дешевле SMS, привычный UX, меньше виртуальных номеров «для сайта».
- После контакта: не 6 картинок, а **1 полный превью + оффер** («пакет 3 ракурса / созвон / счёт»).
- Подписка — отдельный продукт со своим P&L, лимитом GPU, антиабьюзом, офертой, кассой. Не прятать в футер портфолио.
- Скоринг лида: метраж, город, срок, «для себя / для согласования / для продажи». Без этого отдел продаж тонет в «сделай ещё диван».

### 3.3. Альтернативы воронки (лучше, чем телефон-стена)

**A. Квиз планировки (рекомендуемый для студии)**  
Комната → стиль → метраж → «есть планировка?» → загрузка или пропуск → 1 превью → канал связи (TG/телефон) → слот. Квиз сам даёт уникальные данные и квалифицирует. Генерации тратятся на тёплых.

**B. Telegram-бот**  
Сайт даёт 0–1 превью. Продолжение в боте: планировка, правки, оплата. Телефон не спрашиваете — он уже есть. Меньше 152-ФЗ-трения на сайте (но бот — тоже оператор ПДн).

**C. Email magic link**  
Слабее в РФ, но лучше для B2B и зарубежных карт. Не взамен TG, а третья опция.

**D. «Скажи, что не так на рендере»**  
На портфолио: точка на картинке + комментарий → лид с контекстом. Дешевле GPU и ближе к продаже правок.

Не делать: обязательный звонок как единственный путь; 8 бесплатных фотореалов; подписку, которая обесценивает прайс студии.

## 4. Как выйти в топ быстрее, чем «просто 1000 страниц»

1000 URL в один день — способ сжечь краулинговый бюджет и получить МПК. Побеждает **граф + данные + скорость отдачи**, не объём.

1. **Не публиковать 1000 сразу.** 30–50 лучших объектов (полнота полей, свои рендеры) + 6–8 хабов стилей + 3–5 услуг. Индексация, ИКС/GSC, правки шаблона. Потом пачками по 50–100 с гейтом уникальности.
2. **Сначала семантика, потом URL.** Выгрузка Wordstat/Вебмастер: стиль, комната, «визуализация», «дизайн-проект», районы, серии домов. Кластер без частотки = не страница.
3. **Серии домов и районы — недооценённый пласт РФ.** «Кухня П-44Т», «двушка Коломенская лофт» бьют «кухня лофт» по конверсии и проще по конкуренции. Это отдельные кластеры, не теги в облаке.
4. **Ручные столпы.** Хабы стилей, услуги, цены, процесс — не из шаблона. Обновлять раз в квартал. С них вес вниз.
5. **Перелинковка в шаблоне, не сетка всех со всеми.**
   - лист → родительский стиль, родительская комната, 3 «похожих» (серия / метраж / стиль), услуга;
   - кластер → все листья кластера + соседние комнаты этого стиля (лимит 5) + услуга;
   - хаб → кластеры + топ-12 листьев, не 200;
   - листья одного кластера **не** мешат друг друга десятью одинаковыми анкорами.
6. **Уникальность above the fold.** Первые 100–150 слов — факты объекта, не «интерьер — это искусство».
7. **Картинки как поисковый канал.** File name, alt по фактам («кухня 12 м² лофт Кузьминки, рендер 2025»), Image sitemap, сжатие. Яндекс.Картинки для интерьеров — реальный трафик.
8. **Коммерческие сигналы на программных страницах:** цена «от» только если правда и ведёт на `/ceny`; срок; CTA «расчёт по вашей планировке»; не «купить подписку» как главный CTA на портфолио.
9. **Внешние:** Яндекс.Бизнес, карточка с тем же NAP, InMyRoom/Houzz/Дзен с **каноникалом на себя**, не филиалы-дорвеи. 10 нормальных упоминаний студии бьют 1000 тонких URL.
10. **Видеооблёт / 15 сек walkthrough** на топ-20 объектах. Отдельно в выдаче, отдельно доверие.
11. **Яндекс и Google как равные.** Вебмастер + GSC, регион, Турбо не нужен, следить за МПК и «малоценными».
12. **Логи и алерты индексации по сегментам sitemap.** Если `portfolio` индексируется на 30%, не заливать следующую сотню.
13. **Не плодить блог ради блога.** 10 технологических текстов («как считать ракурсы», «что входит в визуализацию») — да. 200 нейростатей — МПК.

## 5. Минимальный набор коммерческих страниц (кроме программных)

Без этого 1000 портфолио — витрина без кассы.

**Индексные (должны быть в топе и в меню):**

1. `/` — кто, для кого, 3 услуги, 8 работ, 1 оффер, доверие (реквизиты/адрес не прятать).
2. `/uslugi` — хаб.
3. `/uslugi/3d-vizualizaciya-interiera` — главная коммерческая.
4. `/uslugi/vizualizaciya-kuhni` (и 2–3 таких, по спросу: квартира, загород, коммерция) — **не** дубль кластеров стиля.
5. `/ceny` — пакеты, что входит, что нет, от чего растёт цена. Без этого коммерция в Яндексе хромает.
6. `/process` — этапы, сроки, правки, исходники.
7. `/portfolio` — каталог (фильтр JS, индексный URL чистый).
8. `/stili` + N хабов.
9. `/o-kompanii` — люди, ИНН, адрес, фото студии/команды.
10. `/kontakty` — NAP, карта, мессенджеры, реквизиты.
11. `/generator` — **одна** посадочная инструмента (как работает, лимиты, примеры, отличие от заказа студии).
12. `/dlya-zastroyshchikov` или `/dlya-dizaynerov` — B2B, если это канал. Иначе не плодить.

**Обязательные юридические (индексные, в футере):**

13. `/oferta`
14. `/politika-konfidencialnosti`
15. `/soglasie-pdn` (текст согласия, версия)
16. `/cookies` (если не в политике)
17. `/requisites` можно совместить с контактами

**Закрытые (`noindex, nofollow`):**

- `/lk/*`, `/pay`, `/checkout`, `/api/*`, квиз-шаги с ПДн, результаты генерации.

**Не обязательно на старте:** блог, «вакансии», 20 лендингов «визуализация в [город]» без офиса в городе (дорвеи).

Если подписка всё же есть: `/tarify-generatora` с честным сравнением «превью vs работа студии», офертой и лимитами GPU. Иначе каннибализация прайса.

```
/                                 # главная
/uslugi
/uslugi/3d-vizualizaciya-interiera
/uslugi/vizualizaciya-kuhni
/ceny
/process
/o-kompanii
/kontakty
/generator                        # один инструмент, index
/tarify-generatora                # только если SaaS живой

/portfolio                        # каталог, без query в индексе
/portfolio/{slug}                 # лист объекта

/stili
/stili/{style}                    # хаб, ручной текст
/stili/{style}/{room}             # кластер: whitelist + порог работ

/komnaty/{room}                   # опционально, если частотка не закрыта стилем

/oferta
/politika-konfidencialnosti
/soglasie-pdn

/lk                               # noindex
```

Слаг листа: `kuhnya-54m-p44t-kuzminki-2025`, не `project-1048` и не `kuhnya-v-stile-loft` (столкновение с кластером).

Каноникал: self на всех открытых. Фильтр-состояние каталога → canonical `/portfolio` или на кластер, если пользователь пришёл из хаба.

Хлебные: Главная → Стили → Лофт → Кухня → объект.

## 7. Контентная модель листа (шаблон, который не doorway)

Порядок блоков на `/portfolio/{slug}`:

1. H1 = объект, не стиль: «Кухня 12 м² в П-44Т, Кузьминки».
2. Паспорт (таблица данных) — то, что уникально.
3. LCP-рендер + 6–12 кадров (lazy).
4. 3 коротких блока: задача / ограничения / решения. Только факты.
5. Материалы списком.
6. Связанные: стиль, комната, 3 объекта, услуга.
7. FAQ: 2–4 вопроса **об этом объекте** (срок, что входило, почему такой свет).
8. CTA заказа студии.
9. Остров генератора (prefill, нижеfold).

Запрещено в шаблоне: абзац «что такое лофт»; одинаковый FAQ на 1000 URL; H1 «Дизайн интерьера под ключ».

## 8. Архитектура генератора (продукт + SEO + деньги)

```
[SEO-страница, SSG] --idle/click--> [виджет-остров]
        |                                |
        |                         POST /api/jobs
        |                                v
        |                         очередь (RF) + квоты
        |                                v
        |                         GPU (лучше РФ) / API
        |                                v
        +-- превью в DOM -------> объект в /lk/jobs/{id} (noindex)
```

Квоты (сервер, не браузер):

| Состояние | Лимит | Выход |
|---|---|---|
| Аноним | 1 preview / 30 дней / fingerprint+IP | водяной знак, без скачивания 4K |
| Контакт подтверждён | +1 полный превью | оффер студии / квиз |
| Подписка | N/мес, жёсткий GPU-бюджет $ | 429 при исчерпании, не «ещё чуть-чуть» |

Prefill из контекста страницы. Upload: MIME whitelist, лимит МБ, антивирус, strip EXIF GPS либо явное согласие на гео. Хранение исходников — срок (например 90 дней), потом удаление.

## 9. Сводка: пробелы / риски / что делать

### Пробелы брифа

- Нет юрконтура 152-ФЗ / 38-ФЗ / 54-ФЗ / локализации / трансгранички GPU.
- Нет модели стоимости и антиабьюза генераций.
- Нет методики «70% уникальности» и гейта публикации.
- Нет политики индексации фильтров (whitelist vs `?`).
- Нет разведения интентов услуга / хаб / кластер / лист.
- Генератор на всех страницах без острова и без `/generator`.
- Воронка отдаёт GPU до лида и ставит телефон стеной.
- Нет серий домов, районов, паспорта объекта.
- Нет минимального коммерческого ядра (цены, процесс, B2B, оферта).
- Смешаны студия и SaaS.

### Риски

- МПК / doorway / каннибализация → не топ, а вылет пачки.
- Штрафы РКН и УФАС (ПДн, реклама на номер).
- Счёт GPU больше выручки.
- CWV красный на всём домене из-за галерей + JS виджета.
- Подписка убивает средний чек студии.
- Мусорные лиды, отдел продаж в ноль.

### Делать в таком порядке

1. Зафиксировать, что продаём в первую очередь: студия (рекомендуется) или SaaS.
2. Юрконтур + хостинг РФ + выбор GPU (РФ или оформленная трансграничка).
3. Коммерческое ядро: услуги, цены, процесс, контакты, 1 генератор-посадочная.
4. 8 хабов стилей вручную + 30–50 листьев с полным паспортом и гейтом уникальности.
5. Кластеры стиль×комната только по семантике и порогу работ.
6. Виджет-остров нижеfold, квоты на сервере, 1 превью, TG/квиз вместо телефон-стены.
7. Sitemap по сегментам, schema по типу, мониторинг индексации.
8. Доливать листья пачками, когда сегмент индексируется и не каннибалит столпы.

Пока нет паспорта объекта, гейта уникальности и политики фасетов — **не генерировать 1000 URL**. Это не масштабирование, это публикация дверных страниц с красивым словом «programmatic».
